# 11 – `plugin-api`, `app` a `ui`

> **Pojmy:** [[Plugin featury]], [[Kompoziční kořen]], [[Neměnná data]], [[Prezentační model]]  
> **Rozhodnutí:** [[0001-jadro-v-cistem-ts]], [[0004-data-oddelene-od-chovani]], [[0009-platformove-nezavisla-domena]], [[0010-prezentacni-model]], [[0011-programovani-proti-rozhranim]]  
> **Milník:** [[M10-ui]]

Nejvyšší vrstvy: jak se pluginy skládají dohromady, kde se aplikace propojí a jak se nad tím staví Vue.

## Plugin featury (plugin-api)

Jednotka rozšiřitelnosti. Každá vrstva má vlastní registr a zná jen svou část pluginu.

```ts
export interface FeaturePlugin<P = unknown> {
  readonly schema: FeatureSchema<P>;          // → FeatureSchemaRegistry (document)
  readonly builder: FeatureBuilder<P>;        // → BuilderRegistry (regen)
  readonly tools?: readonly ToolDescriptor[]; // → ToolRegistry (interaction)
  readonly messages?: PluginMessages;         // { cs: {…}, en: {…} } – texty klíčů ze schématu (ADR 0014)
}
```

Pole přibývají s milníky: M6 má jen `schema` a `builder`, `tools` přidá M9 (až existuje `interaction`), `messages` M10. Pole `ops` (vlastní operace pluginu) původně plánované pro skicář v M12 nevzniká – editace skici je `feature.setParams` ([[Q074 Operace skicáře v logu|Q074]]); přibude, až ho bude potřebovat první plugin (pak `plugin-api` dostane závislost na `ops`).

Registrace jde jedinou funkcí, kterou používá `app` i testy ([[Q047 Registrace pluginu a úplnost registrů|Q047]]):

```ts
export function registerPlugin(
  plugin: FeaturePlugin,
  registries: {
    readonly schemas: FeatureSchemaRegistry;
    readonly builders: BuilderRegistry;
    readonly tools: ToolRegistry;            // od M9
  },
): void;
```

- Od M9 registruje i `plugin.tools` do `ToolRegistry`. Duplicitní id nástroje (i mezi nástroji jednoho pluginu) → výjimka `Duplicate tool '…'` ještě před registrací čehokoli. Pořadí kontrol: typy, schéma, builder, nástroje.

- `plugin.schema.type !== plugin.builder.type` → výjimka (chyba programu), nic se nezaregistruje.
- Duplicitní typ v kterémkoli registru → výjimka (`Duplicate feature schema|builder '…'`) ještě před registrací, takže se nezaregistruje nic (nejdřív se ověří `has` v obou registrech).
- `FeatureBuilder.build` a metody `FeatureSchema` jsou zapsané jako **metody**, ne jako vlastnosti s typem funkce. TS u metod porovnává parametry bivariantně, proto jde `FeaturePlugin<BoxParams>` předat jako `FeaturePlugin` bez přetypování. Přepis na `build: (…) => …` by to rozbil (hlídá test v `plugin-api`).
- Invariant „každý typ má schéma i builder“ tak platí z konstrukce. Kontrolu úplnosti všech pluginů aplikace dělá `app` (M10).

Struktura pluginu:

```
src/features/box/
├─ index.ts          export const boxPlugin: FeaturePlugin<BoxParams>
├─ schema.ts         BoxParams, boxSchema (verze, parametry, defaults, validate)
├─ builder.ts        boxBuilder
├─ tool.ts           boxTool (ToolDescriptor)
└─ box.test.ts       testy builderu s FakeKernel, validace, nástroj s ToolManager
```

Plugin **neobsahuje Vue komponenty**. Formulář dialogu se generuje ze schématu. Pro featuru, které generovaný formulář nestačí, je od M13 v `ui` registr vlastních dialogů podle typu – ne v pluginu ([[#Vlastní dialog featury (úniková cesta)]]).

## Kompoziční kořen (app)

`app` je rozdělený na dvě části (rozhodnutí 2026-10-13):

- **`createAppSession(deps)`** – čisté propojení hotových implementací. Nezná worker ani IndexedDB, takže se testuje v Node s `FakeKernel`, `MemoryDocumentStore` a `FakeViewport` (propojení událostí, regenerace, restart jádra, jen pro čtení).
- **`openAppSession(opts)`** – tenká vrstva pro prohlížeč: vytvoří workery, `IdbDocumentStore`, Web Lock a `Viewport` a předá je `createAppSession`. Testuje ji jen e2e test.

Stav pro UI je jednotně `Observable` ([[0010-prezentacni-model|ADR 0010]]), takže `ui` používá jen `useObservable`. Návrh tvaru (kontrakt upřesní Implementační plán [[M10-ui]]):


Co `createAppSession` dělá:
1. Vytvoří registry, zaregistruje pluginy (`registerPlugin`) a vestavěné handlery operací, ověří úplnost registrů.
2. Načte nebo vytvoří dokument (`loadDocument`). Bez zámku (Q038) dokument jen načte a nevytvoří `PersistenceService`.
3. Sestaví `OperationDispatcher`, `UndoManager`, `PersistenceService`, `Regenerator`, `RegenScheduler`, `ToolManager`, `FeatureEditor`, `ActionRegistry`, prezentační modely a adaptéry portů (`RegenStatusPort` z `RegenState`).
4. Propojí události: `doc.changed` → `RegenScheduler.request()` → `finished` → `viewport.bodies.sync()`; `browser.hidden` → `viewport.setBodyVisible`.
5. Zaregistruje vestavěné akce voláním `createBuiltInActions(deps)` z `interaction` ([[10-interakce#Vestavěné akce]]); pravidla akcí v `app` nejsou (ADR 0010, revize M10).

Pravidla:

- **Jádro startuje na pozadí**: `createAppSession` se vrátí po otevření dokumentu s `kernel: 'starting'`; po `ready` zavolá `viewport.bodies.reset(jádro)` ([[09-vykreslovani]]) a vyžádá regeneraci. Totéž po restartu – viewport tak vždy tesseluje aktuálním jádrem a zahodí cache sítí. `MeshOps` předané `createViewport` v `openAppSession` jsou proto jen zástupné.
- **První pohled**: po první regeneraci, která dá aspoň jedno těleso, `app` jednou zavolá `camera.fitAll()`; další změny kameru nechají, jak ji uživatel nastavil.
- **Potvrzení** (M11): `AppSessionDeps.confirm` (povinné) a `OpenAppSessionOptions.confirm` předá `app` do `createBuiltInActions` ([[10-interakce#Vestavěné akce]]). `ui` (`App.vue`) dodá `({ key, params }) => globalThis.confirm(i18n.global.t(key, params))` – stejný nativní dialog jako mazání dokumentu v `DocumentList`; vlastní dialogová komponenta zatím není potřeba ([[Rozhodnutí noční rychloakce#M11 – Další entity|R16]]).
- **Skicář** (M12, [[12-skicar]], [[10-interakce#Skicář]]): `AppSessionDeps.solver: ConstraintSolver` (povinné; testy `FakeSolver`, prohlížeč `createPlanegcsSolver()` z `openAppSession`). `createAppSession` vytvoří `createSketchEditor({ features, solver, viewport, resolvePlane })` (skicář dostane jen `Pick<ViewportPort, 'sketches'>`, Ú16a) (`resolvePlane` hledá v `ORIGIN_PLANES`), zaregistruje `createSketchTools({ sketches })` do registru nástrojů (za nástroje pluginů) a `createSketchActions`; `ActionRegistry`, `ToolManager` (`defaultToolIds: { sketch: 'sketch.select' }`) a vestavěné akce dostanou `mode`; `FeatureTreeModel` a `BrowserModel` dostanou `sketchEdit: (id) => sketches.edit(id)` a oba `locked` (zábrany editace jsou v presenterech, ne ve `.vue`, Ú16a). Při vstupu do skici `viewport.camera.setViewDirection(session.plane.normal)`. Po každé regeneraci (a při změně `sketches.current`) `app` kreslí `artifactDrawing` každé skici z `sketchesOf(finalState)` pod jejím id, **kromě** právě editované (tu kreslí `SketchEditor`), a odebere kresby skic, které zmizely; `browser.visiblePlanes` → `planeDrawing` pod id roviny / `remove`.
- **Topologické pojmenování, Fillet, Chamfer** (M14, [[08-topologicke-pojmenovani]]): `BUILT_IN_PLUGINS` += fillet, chamfer (na konec). Adaptér portu regenerace plní `RegenBody.names = body.names` (`NameTable` z `regen` strukturálně splňuje `TopoNames`). `createToolManager({ …, regen })`, `bindSelectionHighlight(selection, viewport.highlight, features, regen)` (vybrané hrany v dialogu Filletu a tělesa ve výběru i v poli `bodies` jsou zvýrazněné). `resolvePlane` editoru skici = `planeOfRef(finalState poslední regenerace, ref)` z `regen` (počáteční roviny i rovinné plochy; před první regenerací `EMPTY_STATE`). `createTopoInspector({ viewport, regen })` jako `session.topoInspector`, `dispose` se session.
- **Export a historie** (M15, [[M15-export-a-dokonceni|M15]], [[Rozhodnutí noční rychloakce#M15 – Export a dokončení|R121–R128]]): `AppSessionDeps.download` (povinné; testy zachytávají, `openAppSession` předá `OpenAppSessionOptions.download` z `ui`). `createAppSession` vytvoří `createHistoryModel({ log })` a `createFileActions({ registry: actions, exporter, regen, browser, editor: features, mode })` s exportérem z `file-exporter.ts`:
  - **STEP** (`exportStep(bodies)`): počká, až `RegenScheduler.busy` je `false`, pak **synchronně** vezme poslední `finalState` (týž, ze kterého vznikl poslední `RegenSnapshot`), živé jádro (`KernelSupervisor.kernel()`, `null` → odmítne) a handle těles v pořadí `bodies` (těleso, které ve stavu není, přeskočí; žádné → odmítne) a hned zavolá `kernel.exportStep`. Worker zprávy zpracuje v pořadí, takže `release` pozdější regenerace přijde až po exportu; čekání na nečinnost pokryje sweep, který běží před `finished` ([[07-regenerace#Životnost handle: mark & sweep]]). Výsledek → `download({ name: safeFileName(doc.meta.name) + '.step', mime: 'model/step', data })`.
  - **Dokument** (`exportDocument()`): `flush()` (jen pro čtení nic), `exportStoredDocument(store, docId, { schemas, handlers })` ([[05-persistence#Export a import souboru]]), chyba → odmítne; `download({ name: safeFileName(…) + '.tinycad.json', mime: 'application/json', data: JSON.stringify(file, null, 2) + '\n' })` – odsazení kvůli čitelným rozdílům v gitu.
  - `safeFileName` (interní, čistá): `\ / : * ? " < > |` a řídicí znaky → `_`, ořízne mezery a tečky na koncích, nejvýš 100 znaků, prázdné → `'tinycad'`.
  - **Import** `importDocumentFile(raw, { plugins })` (`browser.ts`; logika v `documents.ts` s `store`, `ids`, `now` pro testy v Node): registry z `createPluginRegistries(plugins)` (`registries.ts`, totéž, co staví `createAppSession`), `importDocument` s novým id; vrací id nového dokumentu nebo chybu dat. `JSON.parse` dělá `ui`.
  - **Barva** (M15, [[Q073 Průhlednost a barva těles|Q073]]): `browser.colors` → `viewport.setBodyColor` (rozdíl proti minulé mapě, jako `hidden`); `defaultBodyColor` z `face` palety podle tématu (`setTheme`).
  - `KernelSupervisor.kernel(): GeometryKernel | null` – živé jádro (během startu, restartu a po selhání `null`); `dispose` session uvolní historii a akce souboru.
- **Vysunutí a Rotace** (M13): `BUILT_IN_PLUGINS` = box, cylinder, transform, boolean, sketch, extrude, revolve. `createAppSession` volá `bindSelectionHighlight(selection, viewport.highlight, features)`, takže oblasti vybrané v dialogu jsou ve viewportu vyplněné ([[10-interakce#Výběr]]); `browser.visibleAxes` → `axisDrawing(osa)` pod id osy / `remove` (stejně jako roviny). Kresby skic z regenerace nesou `regions` samy (`artifactDrawing`).
- **Nový dokument** se jmenuje `translate('document.untitled')` (stejně jako nová featura; přejmenování přijde později).
- **Zavření** (rozhodnutí 2026-10-13): `close()` je asynchronní – dopíše frontu persistence (`flush`), pak uvolní session, a v `openAppSession` až potom store, viewport a zámek. **HMR (vývoj):** při `import.meta.hot.dispose` `App.vue` session zavře přes `close()` a nová instance na to počká, aby nenašla zámek dokumentu obsazený. `flush()` funguje i po `dispose()` a zařadí se za pojistný zápis. `dispose()` zůstává synchronní pojistka: spustí pojistný `flush` a `openAppSession` uvolní store a zámek až po jeho doběhnutí (`.finally`), viewport hned. Druhé `close` vrátí tentýž promise. Selže-li zápis, `close` vše přesto uvolní a odmítne s chybou zápisu – `ui` ji při přepnutí dokumentu zachytí a ukáže. `verify` je v `AppSessionDeps` volitelné (výchozí `false`).
- **Smazání dokumentu** si vezme zámek dokumentu (`ifAvailable`); dokument otevřený jinde nesmaže a odmítne chybou.
- **Kdo co uvolní**: `createAppSession.dispose` uvolní, co sám vytvořil (modely, služby, jádra přes továrnu), a před tím dopíše frontu persistence (`dispose` + `flush`). Viewport, store a zámek předané v `deps` uvolní `openAppSession`, který je vytvořil.
- **Ověření při načtení**: `AppSessionDeps.verify` se předá `loadDocument` ([[05-persistence]]); `openAppSession` ho zapne ve vývojovém režimu (`import.meta.env.DEV`).
- **`RegenScheduler`**: při změně spustí regeneraci; když už běží, poznamená si „dirty“ a po doběhnutí spustí znovu jen jednou (žádná fronta stovek regenerací při tažení posuvníku). Běžící operaci jádra **nepřerušuje** ([[Q010 Zrušení probíhající operace jádra|Q010]]); výsledek zastaralé regenerace se jen zahodí.
- **Restart jádra** ([[Q055 Pád WASM jádra|Q055]]): když jádro skončí `'disconnected'` (trap, pád workeru), `app` ho zahodí, vytvoří nové přes továrnu z `deps`, počká na `ready` a vyžádá regeneraci (`kernel`: `restarting` → `ready`). Opakovaný pád do 10 s → `failed` a UI nabídne obnovení stránky, aby se pády necyklily. Jádro, které se **nespustí** (worker nebo WASM se nenačte, selže inicializace OCCT), je `unavailable` – jiná hláška („Geometrické jádro se nepodařilo spustit“) s technickou chybou v tooltipu; `AppSession.kernelError: Observable<string | null>` nese její text (oprava po chybě v Safari, 2026-10-13). Jádro, které naběhne až po zavření session, se jen uvolní a viewport se nepoužije. Nepovedený restart po pádu je také `unavailable`. U `unavailable` i `failed` nabízí TitleBar obnovení stránky.
- **Jen pro čtení** ([[Q038 Jeden dokument ve dvou záložkách|Q038]], [[05-persistence#Jeden zapisovatel na dokument]]): bez zámku `readOnly: true`, akce a nástroje měnící dokument jsou zakázané.
- **Dokumenty** ([[Q019 Úvodní obrazovka se seznamem dokumentů|Q019]]): bez routeru. Id otevřeného dokumentu je v `location.hash` (`#/d/<id>`), prázdný hash ukáže `DocumentList`. Změnu hashe řeší `ui` (dispose staré session, otevření nové).

## Vue vrstva (ui)

### Pravidla

1. UI čte stav **jen** přes `AppSession` a mění ho **jen** přes jeho API (`features.create`, `actions.run`, `editSession.setParam`…).
2. Doménové objekty, `AppSession` ani objekty Three.js **nikdy** nevkládat do `reactive()`/`ref()` (Vue by je obalilo proxy – rozbije identitu objektů, na které stojí cache regenerace, a zpomalí Three.js). Pokud je nutné je držet v komponentě: `markRaw` nebo `shallowRef`.
3. Reaktivitu zajišťuje jediný composable `useObservable`, který z `Observable<T>` [[Prezentační model|prezentačního modelu]] udělá `shallowRef` ([[0010-prezentacni-model|ADR 0010]]):

```ts
export function useObservable<T>(o: Observable<T>): Readonly<ShallowRef<T>> {
  const value = shallowRef(o.get());
  const off = o.subscribe(() => { value.value = o.get(); });
  onScopeDispose(off);
  return value;
}

// použití
const rows = useObservable(session.featureTree.rows);
```

4. **Komponenta obsahuje jen vazby a rozvržení.** Logika (co se stane po kliknutí, kdy je tlačítko aktivní, jak se řádek stromu zobrazí) patří do prezentačního modelu v `interaction`, kde se testuje bez DOM. Komponenta jen volá příkazy.
5. `AppSession` se do komponent dostane přes `provide/inject` (`useSession()`), ne přes globální proměnnou.
6. Žádný Pinia, dokud není potřeba čistě UI stav sdílený mezi vzdálenými komponentami.

```
├─ FeatureDialog      plovoucí vpravo, přesouvatelný za úchyt; zobrazí se, když
│  │                  features.current != null; tlačítka Zrušit / OK
│  └─ ParamField      podle ParamSpec.kind: LengthField, AngleField, BoolField, EnumField,
│                     PointField, RefListField (tlačítko „aktivní“ stav + u bodies čipy těles
│                     z field.refs a ×, M11), AxisField (M13); skrytá pole se nekreslí,
│                     skupiny mají nadpis (M13); vlastní dialog typu přes dialogFor (M13)
├─ SketchPanel        M12: plovoucí vpravo místo FeatureDialog v režimu skici – jméno skici,
│                     stav („Plně určeno“ / „Stupně volnosti: n“ / hláška), seznam vazeb
│                     (kóty s polem délky, klik = výběr, × = smazat), Zrušit / Hotovo
├─ Timeline           ukotvená dole: FeatureTreeModel vodorovně – ikona featury, název v tooltipu,
│                     stav (ok, chyba s odznakem, potlačeno přeškrtnuté, za barem šedě),
│                     rollback značka tažením, |◀ ◀ ▶ ▶| posouvá bar o krok,
│                     dvojklik = features.edit(id), kontextové menu = akce;
│                     vpravo stav regenerace, počet těles a výběr (nahrazuje StatusBar)
```

- **Start**: `main.ts` volá `startUi('#app', { plugins: BUILT_IN_PLUGINS })`. `BUILT_IN_PLUGINS` exportuje `app` (`ui` nesmí `features`), `ui` exportuje jen `startUi`. Instance vue-i18n patří stránce a startuje s vestavěnými texty; slovníky pluginů přidá `addPluginMessages(i18n, session.messages)` po otevření každé session (kolize klíče s vestavěným = chyba, session se zavře).
- **Klávesnice**: posluchač na `window` převede `keydown` na `ViewKeyEvent` a předá `actions.handleKey`; události z `ViewportHost` přeskočí (ty už jdou přes nástroj a `unhandledKey`, jinak by se akce spustila dvakrát), stejně jako `defaultPrevented` a `isComposing`.
- **Toolbar**: skupiny podle `ToolDescriptor.group` v pořadí `history`, `sketch` (Skica, M12), `feature` (Featury: Vysunutí, Rotace, M13), `primitive` (Vytvořit), `modify` (Transformace, Boolean, od M14 Zaoblení a Zkosení), `construction`, `view`, `select` (Výběr, nechat – přibydou filtry výběru); neznámá skupina na konec, prázdná se nekreslí. Popisek skupiny = klíč `toolbar.group.<id>`. Lišta ukazuje jen nástroje aktuálního režimu (`ToolDescriptor.modes`, výchozí `['model']`). V režimu `sketch` (M12) pořadí `history`, `select`, `draw`, `constrain` (nástroj kóty + akce `sketch.constraint.*` jako tlačítka), `finish` (akce `sketch.cancel`, `sketch.finish`), `view`; čistá funkce `toolbarGroups` dostane `mode`.
  - Vstup `toolbarGroups` (Ú16a): `tools`, `actions`, `actionIds`, `toolActionId`, `toolModes` (= `AppSession.toolModes`; režimy nástroje bez akce, s akcí rozhoduje `ActionState.modes`), `locked`, `mode`, `sketchActionIds`, `sketchConstraintActionId`. Tlačítka skupiny `constrain` za nástrojem kóty jsou **akce skupiny `'sketch.constraint'`** z `actions` v pořadí registrace (žádný opsaný seznam druhů v `ui`); ikona podle druhu, neznámá akce výchozí `link`.
  - `ToolbarItem extends ActionState { group; icon; command }` (`command`: `{ kind: 'action' | 'tool'; id }`), takže menu pod popiskem skupiny zobrazuje přímo `items` skupiny bez převodu.
- **Režim skici** (M12): `FeatureDialog` se v režimu `sketch` nekreslí, místo něj `SketchPanel`; `AppShell` rozhoduje podle `sketchSession !== null` (`useObservable(session.sketches.current)`), ne podle režimu. Pole kóty, jejíž id je v `editingDimension`, dostane fokus a panel zavolá `clearEditingDimension`. Změna hodnoty kóty → `session.setDimension`. Pole kót používají `NumericInput` a `formatNumber` (nejvýš 6 desetinných míst) jako dialog featury. Stavový řádek je `t(state.statusKey, state.statusParams)`; dřívější čistá funkce `sketchStatusText` zanikla, klíč počítá `interaction` (Ú16a, [[0010-prezentacni-model|ADR 0010]]).
- **Dialog**: Enter potvrdí hodnotu pole i dialog (OK), Esc dialog zruší (rozhodnutí 2026-10-13).
- **Přístupnost** (rozhodnutí 2026-10-13): každé pole parametru má přístupný název (`<label>` nebo `aria-labelledby` s přeloženým popiskem, u bodu i osy); ikony `ti` mají `aria-hidden="true"`; stav featury v Timeline (chyba, potlačeno, za barem) a přeložené `issues` jsou v přístupném popisu položky; po otevření dialogu dostane fokus první pole. E2E testy hledají ovládací prvky přes role a přístupné názvy (stavové texty bez role přes text). Chyba pole je navíc v `aria-describedby`/`aria-invalid`.
- **Seznam dokumentů** má stejné přepínače jazyka a režimu jako `TitleBar`; vyhledávání z mockupu až později (rozhodnutí 2026-10-13).
- Pole parametru hlásí změnu (`update`) až po Enteru nebo opuštění pole; neplatný text (prázdný, nečíselný) nehlásí a ukáže zpět poslední hodnotu. Úhel se zadává ve stupních, v dokumentu je v radiánech. `RefListField` navíc vysílá `activate`, který dialog převede na `focusRefParam`.
- Téma (`useTheme`) patří stránce, ne session: `AppShell` při změně tématu zavolá `session.setTheme` ([[Q072 Barvy scény podle režimu|Q072]]).
- `ParamField` je mapovaný v jednom registru `kind → komponenta`. Nový druh parametru = nová komponenta + jeden řádek. Nový typ featury = **nic** v UI. V M10 má komponentu každý `ParamSpec.kind` kromě `region` (rozhodnutí 2026-10-13). M12: `planes` → `RefListField` (jen počet), `data` komponentu nemá a `FeatureDialog` pole bez komponenty přeskočí (test vynechává `data`). M13: `region` → `RefListField` (jen počet, bez čipů, [[Rozhodnutí noční rychloakce#M13 – Extrude a Revolve|R77]] ⚠), `axis` → `AxisField` (tlačítko aktivního stavu jako `RefListField`, text `t(field.refText.key, field.refText.params)`, bez hodnoty „Nevybráno“, × vyšle `update(null)`).
- **Menu Soubor** (M15, [[Rozhodnutí noční rychloakce#M15 – Export a dokončení|R124]]): tlačítko `ti-file-export` s přístupným názvem „Soubor“ v `TitleBar` otevře `ContextMenu` s akcemi `group: 'file'` ze `session.actions` (zakázané šedě). Vedle stav `session.files.status`: `running` „Exportuji…“, `failed` „Export se nezdařil“ (`role="alert"`, technická zpráva v `title`, × → `files.dismiss()`).
- **Stažení** (M15): `ui/download.ts` – `downloadFile(file, env?)`: `Blob` s `file.mime`, `URL.createObjectURL`, klik na dočasný `<a download={name}>`, `revokeObjectURL` až o 1 s později (Safari stahuje asynchronně). Prohlížečové funkce jsou v parametru `env` (`DownloadEnv`), takže logika jde testovat bez DOM. `App.vue` ji předá `openAppSession` jako `download`.
- **Panel historie** (M15, R127, R128): tlačítko `ti-history` („Historie úprav“, `aria-pressed`) v `TitleBar` přepíná `HistoryPanel`; otevření panelu je jen stav rozvržení (`ref` v `AppShell`). Seznam (`role="list"`, nadpis „Historie úprav“) řádků `session.history.state`: čas `HH:MM:SS` (`Intl.DateTimeFormat` podle jazyka), text z čisté `historyText(row, t, te)` (`ui/history-text.ts`: popisek přeložený, existuje-li klíč, jinak surový; `undo` → „Zpět: {label}“, `redo` → „Znovu: {label}“), `undone` šedě kurzívou, `abandoned` přeškrtnuté; při `total > rows.length` patička „Starší záznamy: {n}“. Vestavěné operace mají popisek pod klíčem rovným typu operace (`studio.setRollback`, `body.setColor`…), protože dispečer bez `label` zapisuje typ.
- **Import dokumentu** (M15, R126): `DocumentList` má tlačítko „Importovat“ (`ti-file-import`) a skryté `<input type="file" accept=".json,application/json">`. Přečte text, `JSON.parse` (chyba → „Soubor není platný dokument tinycad“), `importDocumentFile` → `ok` otevře `#/d/<id>`, `err` → stejná hláška a první issue (`path: message`) v `title`.
- **Barva tělesa** (M15, [[Q073 Průhlednost a barva těles|Q073]]): řádek tělesa v `Browser` má `<input type="color">` (`aria-label` „Barva {name}“, hodnota `row.color ?? defaultBodyColor`), změna → `browser.setColor`; s nastavenou barvou tlačítko „Výchozí barva“ (`ti-palette`) → `setColor(body, null)`. Zakázané podle `browser.canEdit`.
- **Ladicí panel jmen** (M14, [[Rozhodnutí noční rychloakce#M14 – Topologické pojmenování|R111]]): `TopoDebugPanel` (malý plovoucí panel vlevo dole) ukazuje z `session.topoInspector.hovered` druh, index, těleso a jméno (`null` → „(bez jména)“, klíč `debug.unnamed`), jméno v `<code>` se zalamováním. Přepínač „Jména ploch“ (`debug.topoNames`) je v `TitleBar` jen při `import.meta.env.DEV` a volá `topoInspector.setEnabled`; panel se kreslí jen při `enabled`. Logika je v `interaction`, komponenta jen čte.
- **Skrytá pole a skupiny** (M13): `FeatureDialog` pole s `field.hidden` nekreslí; před prvním viditelným polem skupiny (jiná `group` než u předchozího viditelného pole; `null` = bez nadpisu) vykreslí nadpis `t(group)` (`role="heading"`, `aria-level` 3). Logika viditelnosti je v `interaction` (`FieldState.hidden`), komponenta jen čte.
- Timeline je jen jiné vykreslení `FeatureTreeModel` z [[10-interakce]], model se kvůli ní nemění. Tooltip featury ukazuje i počet featur, které na ní závisí (`dependents`, M11).
- **Prohlížeč** (M11): jméno `row.userName ?? t(row.name.key, { n })`; dvojklik na jméno zavolá `browser.beginRename`, vložené pole jako v `TimelineItem` se ukáže u řádku `browser.renaming` (Enter a opuštění potvrdí `browser.rename`, Esc → `browser.cancelRename`). Režim přejmenování je stav modelu, ne komponenty ([[Rozhodnutí noční rychloakce#M11 – Další entity|R28]]); komponenta jen porovná text s vyplněným jménem a nezměněný pošle jako `null`. Oko a přejmenování jsou zakázané podle `browser.canEdit`.
- **`RefListField`** (M11) u druhu `bodies`: pod tlačítkem čipy z `field.refs` (`FieldState`, [[10-interakce#Dialog featury: `FeatureEditor`]]) se jménem `label` (`null` → „Chybí těleso“ ve stylu chyby) a tlačítkem × (`aria-label` „Odebrat {name}“), které vyšle `remove` s indexem položky; `FeatureDialog` ho převede na `edit.removeRef(name, index)`. U `topo` jen počet (M14 beze změny – vybrané hrany a plochy ukazuje zvýraznění ve viewportu, čipy chybí, [[Rozhodnutí noční rychloakce#M14 – Topologické pojmenování|R103]] ⚠).
- Prohlížeč potřebuje nový [[Prezentační model|prezentační model]] v `interaction` (tělesa z poslední regenerace přes port, stejně jako `RegenStatusSource`). Kontrakt se upřesní v Implementačním plánu [[M10-ui]].
- Plovoucí panely jsou v DOM **sourozenci** canvasu viewportu, ne jeho potomci. Myš ani kolečko nad panelem se tak k viewportu vůbec nedostanou. Klávesové zkratky v polích panelu odfiltruje už `ActionRegistry` (ignoruje textová pole).

### Vlastní dialog featury (úniková cesta)

Generovaný formulář stačí všem featurám do M15. Kdyby ho některá přerostla (náhled s vlastním ovládáním, víc kroků), dostane vlastní komponentu – v `ui`, ne v pluginu, protože plugin je prstenec 1 a Vue nezná ([[Rozhodnutí noční rychloakce#M13 – Extrude a Revolve|R80]]):

```ts
// ui/components/feature-dialogs.ts
export const FEATURE_DIALOGS: Readonly<Record<string, Component>>;   // featureType → komponenta; v M13 prázdné
export function dialogFor(featureType: string): Component;           // FEATURE_DIALOGS[type] ?? FeatureDialog
```

- `AppShell` vykreslí `dialogFor(edit.schema.type)` s propem `edit: FeatureEditSession`; vlastní komponenta má **stejné rozhraní** jako `FeatureDialog` a stejná pravidla (stav jen přes `useObservable`, změny jen přes příkazy session, logika v prezentačním modelu v `interaction`).
- Kdy ji použít: jen když potřebné chování nejde vyjádřit schématem (`ParamSpec`, `visibleWhen`, `group`) ani novým druhem pole v registru `ParamField`. Nový druh pole je skoro vždy lepší: platí pro všechny featury a test registru ho hlídá. Vlastní dialog je vázaný na jeden typ a jeho logiku je třeba testovat zvlášť.
- Skicář tuto cestu nepoužívá: má vlastní režim (`SketchPanel`), ne dialog featury ([[12-skicar#Režim skicáře (interaction)]]).

### Styl

- Vlastní CSS s proměnnými, žádná UI knihovna. Ikony **Tabler Icons** (jediná UI závislost).
- Vzhled macOS: systémové písmo (`-apple-system`), zaoblené rohy (panely 12 px, ovládací prvky 7–8 px), systémová akcentní modrá, kontextové menu se zkratkami zarovnanými vpravo.
- Toolbar: ikona 24 px v tlačítku 38 px, popisky skupin drobnými verzálkami.
- Plovoucí panely (Prohlížeč, dialog, menu): poloprůhledné pozadí s rozmazáním (`backdrop-filter: blur(18px) saturate(200%)`), krytí v proměnné `--panel-opacity` (výchozí 0,42 světlý, 0,45 tmavý). Ukotvené lišty jsou téměř neprůhledné, působí jako rám okna. Kdyby rozmazání brzdilo orbit, `ui` ho během tažení vypne třídou na kořeni.
- Světlý i tmavý režim: všechny barvy jsou CSS proměnné, režim je atribut na `<html>`, výchozí podle `prefers-color-scheme`. Barvy scény ve viewportu viz [[Q072 Barvy scény podle režimu|Q072]].
- Jazyk: čeština a angličtina, přepínač v TitleBar. Mechanismus viz [[Q070 Překlady textů UI|Q070]].
