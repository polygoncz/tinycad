# 11 – `plugin-api`, `app` a `ui`

> **Pojmy:** [[Plugin featury]], [[Kompoziční kořen]], [[Neměnná data]], [[Prezentační model]]  
> **Rozhodnutí:** [[0001-jadro-v-cistem-ts]], [[0004-data-oddelene-od-chovani]], [[0009-platformove-nezavisla-domena]], [[0010-prezentacni-model]], [[0011-programovani-proti-rozhranim]]  
> **Milník:** [[M10-ui]]

Nejvyšší vrstvy: jak se pluginy skládají dohromady, kde se aplikace propojí a jak se nad tím staví Vue.

## Plugin featury (plugin-api)

Jednotka rozšiřitelnosti. Každá vrstva má vlastní registr a zná jen svou část pluginu.

```ts
export interface FeaturePlugin<P = unknown> {
  readonly schema: FeatureSchema<P>;          // → FeatureSchemaRegistry (document)
  readonly builder: FeatureBuilder<P>;        // → BuilderRegistry (regen)
  readonly tools?: readonly ToolDescriptor[]; // → ToolRegistry (interaction)
  readonly ops?: readonly OpHandler[];        // vlastní operace (skicář) → OpHandlerRegistry
  readonly messages?: PluginMessages;         // { cs: {…}, en: {…} } – texty klíčů ze schématu (ADR 0014)
}
```

Pole přibývají s milníky: M6 má jen `schema` a `builder`, `tools` přidá M9 (až existuje `interaction`), `ops` M12 (skicář; `plugin-api` pak potřebuje závislost na `ops`).

Registrace jde jedinou funkcí, kterou používá `app` i testy ([[Q047 Registrace pluginu a úplnost registrů|Q047]]):

```ts
export function registerPlugin(
  plugin: FeaturePlugin,
  registries: {
    readonly schemas: FeatureSchemaRegistry;
    readonly builders: BuilderRegistry;
    readonly tools: ToolRegistry;            // od M9
  },
): void;
```

- Od M9 registruje i `plugin.tools` do `ToolRegistry`. Duplicitní id nástroje (i mezi nástroji jednoho pluginu) → výjimka `Duplicate tool '…'` ještě před registrací čehokoli. Pořadí kontrol: typy, schéma, builder, nástroje.

- `plugin.schema.type !== plugin.builder.type` → výjimka (chyba programu), nic se nezaregistruje.
- Duplicitní typ v kterémkoli registru → výjimka (`Duplicate feature schema|builder '…'`) ještě před registrací, takže se nezaregistruje nic (nejdřív se ověří `has` v obou registrech).
- `FeatureBuilder.build` a metody `FeatureSchema` jsou zapsané jako **metody**, ne jako vlastnosti s typem funkce. TS u metod porovnává parametry bivariantně, proto jde `FeaturePlugin<BoxParams>` předat jako `FeaturePlugin` bez přetypování. Přepis na `build: (…) => …` by to rozbil (hlídá test v `plugin-api`).
- Invariant „každý typ má schéma i builder“ tak platí z konstrukce. Kontrolu úplnosti všech pluginů aplikace dělá `app` (M10).

Struktura pluginu:

```
src/features/box/
├─ index.ts          export const boxPlugin: FeaturePlugin<BoxParams>
├─ schema.ts         BoxParams, boxSchema (verze, parametry, defaults, validate)
├─ builder.ts        boxBuilder
├─ tool.ts           boxTool (ToolDescriptor)
└─ box.test.ts       testy builderu s FakeKernel, validace, nástroj s ToolManager
```

Plugin **neobsahuje Vue komponenty**. Formulář dialogu se generuje ze schématu. (Pokud by featura někdy potřebovala vlastní UI, přidá se mechanismus registrace komponent podle typu v `ui` – ne v pluginu.)

## Kompoziční kořen (app)

`app` je rozdělený na dvě části (rozhodnutí 2026-10-13):

- **`createAppSession(deps)`** – čisté propojení hotových implementací. Nezná worker ani IndexedDB, takže se testuje v Node s `FakeKernel`, `MemoryDocumentStore` a `FakeViewport` (propojení událostí, regenerace, restart jádra, jen pro čtení).
- **`openAppSession(opts)`** – tenká vrstva pro prohlížeč: vytvoří workery, `IdbDocumentStore`, Web Lock a `Viewport` a předá je `createAppSession`. Testuje ji jen e2e test.

Stav pro UI je jednotně `Observable` ([[0010-prezentacni-model|ADR 0010]]), takže `ui` používá jen `useObservable`. Návrh tvaru (kontrakt upřesní Implementační plán [[M10-ui]]):

```ts
export type RegenUiState = { readonly busy: boolean; readonly bodyCount: number; readonly errorCount: number; readonly lastMs: number | null };
export type KernelUiState = 'starting' | 'ready' | 'restarting' | 'failed';

export interface AppSession extends Disposable {
  readonly doc: DocumentReader;
  readonly readOnly: boolean;                          // Q038: dokument otevřený v jiné záložce
  readonly regen: Observable<RegenUiState>;
  readonly kernel: Observable<KernelUiState>;          // Q055: restart po pádu jádra
  readonly persistence: Observable<PersistenceStatus>; // 'saved' | 'pending' | 'error'
  readonly selection: SelectionModel;
  readonly featureTree: FeatureTreeModel;              // Timeline
  readonly browser: BrowserModel;                      // Prohlížeč, viditelnost těles (Q071)
  readonly tools: ToolManager;
  readonly toolList: readonly ToolDescriptor[];
  readonly features: FeatureEditor;
  readonly actions: ActionRegistry;
  readonly messages: PluginMessages;                   // slovníky pluginů pro vue-i18n (ADR 0014)

  mountViewport(el: HTMLElement): void;
  flush(): Promise<void>;                              // dopíše frontu persistence hned (jen pro čtení: nic); openAppSession ho volá na pagehide / visibilitychange=hidden
  close(): Promise<void>;                              // dopíše frontu persistence a uvolní vše; ui na něj čeká při přepnutí dokumentu
  setTheme(theme: 'light' | 'dark'): void;            // Q072: app vybere ScenePalette, ui nezná render
  dispose(): void;
}

export function createAppSession(deps: AppSessionDeps): Promise<AppSession>;   // Node i prohlížeč
export function openAppSession(opts: {
  docId: DocumentId; plugins: readonly FeaturePlugin[];
  translate: (key: string) => string; theme: 'light' | 'dark';   // název nového dokumentu, počáteční paleta
}): Promise<AppSession>;                                                       // jen prohlížeč
export function listDocuments(): Promise<readonly DocumentInfo[]>;
export function createNewDocument(opts: { translate: (key: string) => string }): Promise<DocumentId>;
export function deleteDocument(id: DocumentId): Promise<void>;   // odmítne dokument otevřený v jiné záložce (zámek)
```

Co `createAppSession` dělá:
1. Vytvoří registry, zaregistruje pluginy (`registerPlugin`) a vestavěné handlery operací, ověří úplnost registrů.
2. Načte nebo vytvoří dokument (`loadDocument`). Bez zámku (Q038) dokument jen načte a nevytvoří `PersistenceService`.
3. Sestaví `OperationDispatcher`, `UndoManager`, `PersistenceService`, `Regenerator`, `RegenScheduler`, `ToolManager`, `FeatureEditor`, `ActionRegistry`, prezentační modely a adaptéry portů (`RegenStatusPort` z `RegenState`).
4. Propojí události: `doc.changed` → `RegenScheduler.request()` → `finished` → `viewport.bodies.sync()`; `browser.hidden` → `viewport.setBodyVisible`.
5. Zaregistruje vestavěné akce: undo, redo, smazat vybranou featuru, potlačit, fit all, aktivace nástrojů podle zkratek z `ToolDescriptor`.

Pravidla:

- **Jádro startuje na pozadí**: `createAppSession` se vrátí po otevření dokumentu s `kernel: 'starting'`; po `ready` zavolá `viewport.bodies.reset(jádro)` ([[09-vykreslovani]]) a vyžádá regeneraci. Totéž po restartu – viewport tak vždy tesseluje aktuálním jádrem a zahodí cache sítí. `MeshOps` předané `createViewport` v `openAppSession` jsou proto jen zástupné.
- **První pohled**: po první regeneraci, která dá aspoň jedno těleso, `app` jednou zavolá `camera.fitAll()`; další změny kameru nechají, jak ji uživatel nastavil.
- **Nový dokument** se jmenuje `translate('document.untitled')` (stejně jako nová featura; přejmenování přijde později).
- **Zavření** (rozhodnutí 2026-10-13): `close()` je asynchronní – dopíše frontu persistence (`flush`), pak uvolní session, a v `openAppSession` až potom store, viewport a zámek. `dispose()` zůstává synchronní pojistka (nečeká na zápis). Druhé `close` vrátí tentýž promise. Selže-li zápis, `close` vše přesto uvolní a odmítne s chybou zápisu – `ui` ji při přepnutí dokumentu zachytí a ukáže. `verify` je v `AppSessionDeps` volitelné (výchozí `false`).
- **Smazání dokumentu** si vezme zámek dokumentu (`ifAvailable`); dokument otevřený jinde nesmaže a odmítne chybou.
- **Kdo co uvolní**: `createAppSession.dispose` uvolní, co sám vytvořil (modely, služby, jádra přes továrnu), a před tím dopíše frontu persistence (`dispose` + `flush`). Viewport, store a zámek předané v `deps` uvolní `openAppSession`, který je vytvořil.
- **Ověření při načtení**: `AppSessionDeps.verify` se předá `loadDocument` ([[05-persistence]]); `openAppSession` ho zapne ve vývojovém režimu (`import.meta.env.DEV`).
- **`RegenScheduler`**: při změně spustí regeneraci; když už běží, poznamená si „dirty“ a po doběhnutí spustí znovu jen jednou (žádná fronta stovek regenerací při tažení posuvníku). Běžící operaci jádra **nepřerušuje** ([[Q010 Zrušení probíhající operace jádra|Q010]]); výsledek zastaralé regenerace se jen zahodí.
- **Restart jádra** ([[Q055 Pád WASM jádra|Q055]]): když jádro skončí `'disconnected'` (trap, pád workeru), `app` ho zahodí, vytvoří nové přes továrnu z `deps`, počká na `ready` a vyžádá regeneraci (`kernel`: `restarting` → `ready`). Opakovaný pád do 10 s → `failed` a UI nabídne obnovení stránky, aby se pády necyklily.
- **Jen pro čtení** ([[Q038 Jeden dokument ve dvou záložkách|Q038]], [[05-persistence#Jeden zapisovatel na dokument]]): bez zámku `readOnly: true`, akce a nástroje měnící dokument jsou zakázané.
- **Dokumenty** ([[Q019 Úvodní obrazovka se seznamem dokumentů|Q019]]): bez routeru. Id otevřeného dokumentu je v `location.hash` (`#/d/<id>`), prázdný hash ukáže `DocumentList`. Změnu hashe řeší `ui` (dispose staré session, otevření nové).

## Vue vrstva (ui)

### Pravidla

1. UI čte stav **jen** přes `AppSession` a mění ho **jen** přes jeho API (`features.create`, `actions.run`, `editSession.setParam`…).
2. Doménové objekty, `AppSession` ani objekty Three.js **nikdy** nevkládat do `reactive()`/`ref()` (Vue by je obalilo proxy – rozbije identitu objektů, na které stojí cache regenerace, a zpomalí Three.js). Pokud je nutné je držet v komponentě: `markRaw` nebo `shallowRef`.
3. Reaktivitu zajišťuje jediný composable `useObservable`, který z `Observable<T>` [[Prezentační model|prezentačního modelu]] udělá `shallowRef` ([[0010-prezentacni-model|ADR 0010]]):

```ts
export function useObservable<T>(o: Observable<T>): Readonly<ShallowRef<T>> {
  const value = shallowRef(o.get());
  const off = o.subscribe(() => { value.value = o.get(); });
  onScopeDispose(off);
  return value;
}

// použití
const rows = useObservable(session.featureTree.rows);
```

4. **Komponenta obsahuje jen vazby a rozvržení.** Logika (co se stane po kliknutí, kdy je tlačítko aktivní, jak se řádek stromu zobrazí) patří do prezentačního modelu v `interaction`, kde se testuje bez DOM. Komponenta jen volá příkazy.
5. `AppSession` se do komponent dostane přes `provide/inject` (`useSession()`), ne přes globální proměnnou.
6. Žádný Pinia, dokud není potřeba čistě UI stav sdílený mezi vzdálenými komponentami.

### Komponenty

```
AppShell
├─ TitleBar           název dokumentu + tečka stavu uložení (zelená uloženo, oranžová rozpracováno,
│                     červená chyba), vstup do seznamu dokumentů, přepínač jazyka a režimu
├─ Toolbar            ukotvený; nástroje ze session.toolList seskupené podle group
│                     (Historie, Vytvořit, Upravit, Konstrukce, Zobrazit), ikona bez popisku
│                     + tooltip „název  zkratka“, pod skupinou popisek s rozbalovací nabídkou;
│                     undo/redo a fit all z actions; záložky Modelování/Skica až od M12
├─ ViewportHost       <div ref>, onMounted → session.mountViewport(el); celá plocha pod lištou
├─ Browser            plovoucí vlevo: dokument › Tělesa › Těleso n; klik = výběr tělesa,
│                     oko = viditelnost (Q071); Počátek a Skici přibydou s M11/M12
├─ FeatureDialog      plovoucí vpravo, přesouvatelný za úchyt; zobrazí se, když
│  │                  features.current != null; tlačítka Zrušit / OK
│  └─ ParamField      podle ParamSpec.kind: LengthField, AngleField, BoolField, EnumField,
│                     PointField, RefListField (seznam vybraných referencí + „aktivní“ stav)
├─ Timeline           ukotvená dole: FeatureTreeModel vodorovně – ikona featury, název v tooltipu,
│                     stav (ok, chyba s odznakem, potlačeno přeškrtnuté, za barem šedě),
│                     rollback značka tažením, |◀ ◀ ▶ ▶| posouvá bar o krok,
│                     dvojklik = features.edit(id), kontextové menu = akce;
│                     vpravo stav regenerace, počet těles a výběr (nahrazuje StatusBar)
└─ DocumentList       plovoucí list přes viewport: karty dokumentů, nový, otevřít, smazat
```

- **Start**: `main.ts` volá `startUi('#app', { plugins: BUILT_IN_PLUGINS })`. `BUILT_IN_PLUGINS` exportuje `app` (`ui` nesmí `features`), `ui` exportuje jen `startUi`. Instance vue-i18n patří stránce a startuje s vestavěnými texty; slovníky pluginů přidá `addPluginMessages(i18n, session.messages)` po otevření každé session (kolize klíče s vestavěným = chyba, session se zavře).
- **Klávesnice**: posluchač na `window` převede `keydown` na `ViewKeyEvent` a předá `actions.handleKey`; události z `ViewportHost` přeskočí (ty už jdou přes nástroj a `unhandledKey`, jinak by se akce spustila dvakrát), stejně jako `defaultPrevented` a `isComposing`.
- **Toolbar**: skupiny podle `ToolDescriptor.group` v pořadí `history`, `primitive` (Vytvořit), `modify`, `construction`, `view`, `select` (Výběr, nechat – přibydou filtry výběru); neznámá skupina na konec, prázdná se nekreslí. Popisek skupiny = klíč `toolbar.group.<id>`.
- **Dialog**: Enter potvrdí hodnotu pole i dialog (OK), Esc dialog zruší (rozhodnutí 2026-10-13).
- **Přístupnost** (rozhodnutí 2026-10-13): každé pole parametru má přístupný název (`<label>` nebo `aria-labelledby` s přeloženým popiskem, u bodu i osy); ikony `ti` mají `aria-hidden="true"`; stav featury v Timeline (chyba, potlačeno, za barem) a přeložené `issues` jsou v přístupném popisu položky; po otevření dialogu dostane fokus první pole. E2E testy hledají ovládací prvky přes role a přístupné názvy (stavové texty bez role přes text). Chyba pole je navíc v `aria-describedby`/`aria-invalid`.
- **Seznam dokumentů** má stejné přepínače jazyka a režimu jako `TitleBar`; vyhledávání z mockupu až později (rozhodnutí 2026-10-13).
- Pole parametru hlásí změnu (`update`) až po Enteru nebo opuštění pole; neplatný text (prázdný, nečíselný) nehlásí a ukáže zpět poslední hodnotu. Úhel se zadává ve stupních, v dokumentu je v radiánech. `RefListField` navíc vysílá `activate`, který dialog převede na `focusRefParam`.
- Téma (`useTheme`) patří stránce, ne session: `AppShell` při změně tématu zavolá `session.setTheme` ([[Q072 Barvy scény podle režimu|Q072]]).
- `ParamField` je mapovaný v jednom registru `kind → komponenta`. Nový druh parametru = nová komponenta + jeden řádek. Nový typ featury = **nic** v UI. V M10 má komponentu každý `ParamSpec.kind` kromě `region` (přijde se skicářem v [[M12-skicar]]); test registru `region` výslovně vynechává (rozhodnutí 2026-10-13).
- Timeline je jen jiné vykreslení `FeatureTreeModel` z [[10-interakce]], model se kvůli ní nemění.
- Prohlížeč potřebuje nový [[Prezentační model|prezentační model]] v `interaction` (tělesa z poslední regenerace přes port, stejně jako `RegenStatusSource`). Kontrakt se upřesní v Implementačním plánu [[M10-ui]].
- Plovoucí panely jsou v DOM **sourozenci** canvasu viewportu, ne jeho potomci. Myš ani kolečko nad panelem se tak k viewportu vůbec nedostanou. Klávesové zkratky v polích panelu odfiltruje už `ActionRegistry` (ignoruje textová pole).

### Styl

- Vlastní CSS s proměnnými, žádná UI knihovna. Ikony **Tabler Icons** (jediná UI závislost).
- Vzhled macOS: systémové písmo (`-apple-system`), zaoblené rohy (panely 12 px, ovládací prvky 7–8 px), systémová akcentní modrá, kontextové menu se zkratkami zarovnanými vpravo.
- Toolbar: ikona 24 px v tlačítku 38 px, popisky skupin drobnými verzálkami.
- Plovoucí panely (Prohlížeč, dialog, menu): poloprůhledné pozadí s rozmazáním (`backdrop-filter: blur(18px) saturate(200%)`), krytí v proměnné `--panel-opacity` (výchozí 0,42 světlý, 0,45 tmavý). Ukotvené lišty jsou téměř neprůhledné, působí jako rám okna. Kdyby rozmazání brzdilo orbit, `ui` ho během tažení vypne třídou na kořeni.
- Světlý i tmavý režim: všechny barvy jsou CSS proměnné, režim je atribut na `<html>`, výchozí podle `prefers-color-scheme`. Barvy scény ve viewportu viz [[Q072 Barvy scény podle režimu|Q072]].
- Jazyk: čeština a angličtina, přepínač v TitleBar. Mechanismus viz [[Q070 Překlady textů UI|Q070]].
