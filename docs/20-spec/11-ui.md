## Plugin featury (plugin-api)

Jednotka rozšiřitelnosti na straně klienta. Od [[M47-uklid-a-dokonceni|M47]] je plugin jen **klientská půlka typu featury** ([[Rozhodnutí nativního jádra|N123]]): schéma a builder má jádro v C++ (`server/src/features/<typ>`, [[07-regenerace]]) a klient bere schéma z popisu typu, který pošle server (`FeatureTypeDescriptor` → `featureSchemaOf` v `remote`, [[Rozhodnutí nativního jádra|N67]], [[14-protokol]]). Plugin dává jen to, co server neumí.

```ts
// src/plugin-api/plugin.ts
export interface FeaturePlugin<P = unknown, A extends FeatureAnchors = FeatureAnchors> {
  readonly type: string;                                 // typ featury jádra, ke kterému plugin patří
  readonly tools?: readonly ToolDescriptor[];            // → ToolRegistry (interaction)
  readonly messages?: PluginMessages;                    // { cs: {…}, en: {…} } – texty klíčů ze schématu a vlastních kódů issues (ADR 0014)
  readonly manipulators?: ManipulatorDescriptor<P, A>;   // → ManipulatorRegistry (interaction), jeho type = typ featury (M18)
}
```

`P` je typ parametrů pluginu (`params.ts`), `A` typ kotev, které počítá jádro a čte deskriptor úchytů (`anchors.ts`), takže překlep ve jménu kotvy je chyba typu ([[0021-manipulatory-kotvy-z-regenerace|ADR 0021]], dodatek). Plugin bez manipulátoru `A` neuvádí. Plugin skici má jen `type` a `messages` a je bez typu parametrů (`features/*` nesmí záviset na `sketch`, [[Rozhodnutí nativního jádra|N139]]). Pole `ops` (vlastní operace pluginu) nevzniká – editace skici je `feature.setParams` ([[Q074 Operace skicáře v logu|Q074]]).

**Registrace** (`createRemoteRegistries` v `src/app/remote-registries.ts`; do M46 `registerPlugin`, viz [[11-ui v prohlížeči]]): schémata z popisů typů serveru, nástroj výběru a za ním nástroje pluginů, manipulátory a sloučené slovníky. Handlery operací běží nad těmito schématy v optimistickém zrcadle ([[Rozhodnutí nativního jádra|N63]]). Schéma s verzí > 1 dostane `migrate`, který jen vyhodí – migruje jádro ([[Rozhodnutí nativního jádra|N87]]). Plugin typu, který server nezná, se přeskočí s varováním v konzoli (starší server, plugin ve vývoji). Duplicitní typ schématu, id nástroje nebo klíč zprávy je chyba programu (výjimka).

**Soulad klienta a serveru** hlídá `test/unit/app/plugins.test.ts`: typy `BUILT_IN_PLUGINS` = typy zlatého souboru popisů `test/golden/feature-types.json`, který zapisuje C++ test ([[Rozhodnutí nativního jádra|N95]]). Nový typ featury bez klientské půlky (nebo plugin bez typu na serveru) tak test shodí.

Struktura pluginu:

```
src/features/extrude/
├─ index.ts          export const extrudePlugin: FeaturePlugin<ExtrudeParams, ExtrudeAnchors>
├─ params.ts         ExtrudeParams a čisté pomůcky nad parametry (třeba flipApplies)
├─ anchors.ts        ExtrudeAnchors (jen u pluginů s manipulátorem)
├─ tool.ts           extrudeTool (ToolDescriptor)
├─ manipulators.ts   extrudeManipulators (jen u pluginů s manipulátorem)
└─ messages.ts       extrudeMessages (cs, en)

test/unit/features/extrude/extrude.test.ts   nástroj s ToolManager, manipulátor, pomůcky z params.ts
```

Plugin **neobsahuje Vue komponenty**. Formulář dialogu se generuje ze schématu. Pro featuru, které generovaný formulář nestačí, je od M13 v `ui` registr vlastních dialogů podle typu – ne v pluginu ([[#Vlastní dialog featury (úniková cesta)]]).

## Kompoziční kořen (app)

Od [[M46-klient-nad-read-modelem|M46]] je server jediná cesta aplikace ([[Rozhodnutí nativního jádra|N68]]) a [[M47-uklid-a-dokonceni|M47]] smazal lokální kořen s jádrem OCCT ve workeru, IndexedDB, Web Lockem a regenerací v prohlížeči (popis do M46 v [[11-ui v prohlížeči]]). `app` má dvě části:

- **`createRemoteAppSession(deps)`** (`remote-session.ts`) – čisté propojení nad sezením jádra (`openRemoteSession` z `remote`, [[14-protokol]]). Nezná DOM: transport, viewport, časovače a úložiště id sezení dostane v `deps`, takže se testuje v Node nad `createFakeCore()` z `@/remote/testing`, `FakeAppViewport` z `app/testing.ts` a `FakeSolver`.
- **`openAppSession(opts)`** (`browser.ts`) – tenká vrstva pro prohlížeč: vytvoří gRPC-Web transport k jádru (`createCoreTransport(VITE_CORE_URL || '/api')`), `Viewport`, řešič planegcs ve workeru (`createPlanegcsSolver()`, worker naběhne při prvním řešení, [[Rozhodnutí nativního jádra|N120]]), obrysy textu nad přibalenými fonty (`createOpentypeOutliner`), geometrii skici přes `GeometryService` (`createRemoteSketchGeometry`) a `sessionStorage` pro navázání sezení po reloadu ([[Rozhodnutí nativního jádra|N70]]), a předá je `createRemoteAppSession`. Testuje ji jen e2e (proti Docker Compose).

Stav pro UI je jednotně `Observable` ([[0010-prezentacni-model|ADR 0010]]), takže `ui` používá jen `useObservable`. Typy fasády jsou v `src/app/app-session.ts` (přestěhované beze změny tvaru z lokální session):

```ts
export type RegenUiState = { readonly busy: boolean; readonly bodyCount: number; readonly lastMs: number | null };  // počet chyb je od M19.2 FeatureTreeModel.errorCount; failed zrušeno v M48 (N153)
export type KernelUiState = 'starting' | 'ready' | 'restarting' | 'unavailable';   // stav spojení (N69); 'failed' zrušeno v M48 (N153)
export type PersistenceStatus = 'saved' | 'pending' | 'error' | 'failed';                     // změny v letu (N69, N92)

export interface AppSession extends Disposable {
  readonly doc: DocumentReader;                        // optimistické zrcadlo (MirrorDocument, N63)
  readonly readOnly: boolean;                          // Q102: sezení není zapisovatelné (dokument drží jiná záložka)
  readonly locked: Observable<boolean>;                // readOnly || otevřený dialog – jediné místo pravidla (interaction)
  readonly toolbar: Omit<ToolbarModel, 'dispose'>;   // M20: lišta nástrojů (10-interakce); konstanty akcí bere ui z @/interaction/constants
  readonly regen: Observable<RegenUiState>;
  readonly kernel: Observable<KernelUiState>;
  readonly kernelError: Observable<string | null>;     // text poslední chyby u 'unavailable'
  retryKernel(): void;                                 // nový pokus o spojení (session.refresh())
  readonly persistence: Observable<PersistenceStatus>; // jen pro čtení: vždy 'saved'
  readonly persistenceError: Observable<string | null>; // text poslední chyby u 'error' a 'failed'
  readonly notices: Observable<readonly AppNotice[]>;  // M48: dočasná hlášení (toast), nejstarší první (N151)
  dismissNotice(id: number): void;                     // M48: uživatel hlášení zavřel; neznámé id nic
  readonly selection: SelectionModel;
  readonly featureTree: FeatureTreeModel;              // Timeline
  readonly browser: BrowserModel;                      // Prohlížeč, viditelnost těles (Q071)
  readonly features: FeatureEditor;
  readonly actions: Pick<ActionRegistry, 'actions' | 'run' | 'handleKey'>;   // ui akce jen čte, spouští a předává klávesy
  readonly messages: PluginMessages;                   // slovníky pluginů pro vue-i18n (ADR 0014)
  readonly sketches: Omit<SketchEditor, 'gridStep'>;   // M12: skicář (panel skici, režim); krok mřížky čtou jen nástroje (M19.2)
  readonly mode: Observable<Mode>;                     // M12: = sketches.mode; Toolbar, dialog vs. panel skici
  readonly topoInspector: Omit<TopoInspector, 'dispose'>;   // M14: ladicí panel jmen
  readonly history: Omit<HistoryModel, 'dispose'>;     // M15: panel historie úprav nad historií serveru (N73)
  readonly files: Omit<FileActions, 'dispose'>;        // M15: stav exportu (akce jsou v actions, skupina 'file')
  readonly defaultBodyColor: Observable<string>;       // '#rrggbb' barvy ploch aktuální palety, pro pole barvy v Prohlížeči
  readonly documentName: Omit<DocumentNameModel, 'dispose'>;   // M19.2: jméno dokumentu a jeho přejmenování (document.rename, mimo undo)
  readonly manipulator: { hud; setMode(id); setValue(handleId, shown); project(world); onViewChanged(listener) };   // M19
  readonly tools: { readonly hint: Observable<ToolHint | null> };   // M37: nápověda aktivního nástroje
  readonly view: {                                     // M19.2 D4: průmět do pohledu pro vše, co ui kreslí nad viewportem (kóty skici)
    project(world: Vec3): readonly [x: number, y: number] | null;
    onViewChanged(listener: () => void): Unsubscribe;
  };

  mountViewport(el: HTMLElement): void;
  flush(): Promise<void>;                              // počká na prázdnou frontu změn; při 'failed' odmítne
  close(): Promise<void>;                              // flush, pak CloseSession na jádře a uvolnění; ui na něj čeká při přepnutí dokumentu
  readonly viewSettings: ViewSettings;                // téma, popisky view cube, režim otáčení, styl zobrazení, AO (M20 D7, M22, M23)
  dispose(): void;                                     // synchronní pojistka: uvolní hned, CloseSession best effort
}

export function openAppSession(opts: {
  docId: DocumentId; plugins: readonly FeaturePlugin[];
  translate: (key: string) => string; theme: 'light' | 'dark';   // název nové featury, počáteční paleta
  confirm: (request: ConfirmRequest) => boolean;                  // potvrzovací dotaz akcí (M11), ui: globalThis.confirm + překlad
  download: (file: DownloadFile) => void;                         // M15: stažení souboru, ui: Blob + <a download>
}): Promise<AppSession>;                                           // jen prohlížeč
export function createDocumentList(opts: { translate: (key: string) => string; confirm: (request: ConfirmRequest) => boolean | Promise<boolean> }): DocumentListModel;   // model seznamu dokumentů nad DocumentService (10-interakce)
/** M15: typy vestavěných operací (klíče OP_VERSION včetně 'batch'); ui nesmí ops, test překladů je bere odtud. */
export const BUILT_IN_OPERATION_TYPES: readonly string[];
export const BUILT_IN_PLUGINS: readonly FeaturePlugin[];

/** M15: port stažení souboru; implementuje ui (app ani interaction DOM neznají). */

```

Kroky:
1. `openRemoteSession` otevře sezení dokumentu (s `resume_session_id` z `sessionStorage`, [[Rozhodnutí nativního jádra|N70]]); navázané sezení s otevřenou transakcí předchozí stránky se nejdřív zruší `Abort`em ([[Rozhodnutí nativního jádra|N135]]).
2. Registry z popisů typů sezení a pluginů (`createRemoteRegistries`). `readOnly = !readModel.session.writable`.
3. Sestaví `MirrorDocument`, stav spojení, `RemoteDispatcher` (jen pro čtení obalený `refuseChanges`), `createReadModelView`, `ToolManager`, `FeatureEditor`, `SketchEditor`, `ActionRegistry`, prezentační modely, historii a exportér.
4. Propojí události: každý nový read model sezení → `view.show(readModel)` (viz *Krok zobrazení*); otevření a zavření dialogu featury → nové čtení read modelu s `input_of` a bez něj ([[0025-vstupni-stav-editovane-featury|ADR 0025]]); `browser.hidden` a další mapy → `viewport-mirror`.
5. Zaregistruje vestavěné akce voláním `createBuiltInActions(deps)` z `interaction` ([[10-interakce#Vestavěné akce]]); pravidla akcí v `app` nejsou (ADR 0010, revize M10).

Regeneraci, plánovač a restart jádra klient nemá: regeneruje server po každé přijaté změně ([[07-regenerace]]) a klient vidí výsledek jen v read modelu ([[14-protokol]]).

Pravidla:

- **Stav jádra a ukládání** ([[Rozhodnutí nativního jádra|N69]], `connection-state.ts`): stav spojení `RemoteSession.connection` se mapuje na `kernel` – připojuji = `starting`, online = `ready`, opakuji = `restarting`, nedostupný = `unavailable`. Změny ve frontě a v letu (`RemoteSession.pending`) se mapují na `persistence`: opakování = `error`, offline se změnami ve frontě nebo se změnou zahozenou kvůli výpadku = `failed`, jinak změny v letu = `pending`, žádné = `saved`. `failed` se vynuluje, až je spojení zpět online ([[Rozhodnutí nativního jádra|N92]], [[Rozhodnutí nativního jádra|N134]]). `kernelError` nese text poslední chyby jen v `unavailable`, `persistenceError` jen v `error` a `failed`. `retryKernel()` zavolá `session.refresh()` (nový pokus o spojení), jeho chybu poznamená do stavu. Titulek a banner tak zůstaly beze změny, `ui` dostalo jen nové texty ([[#Komponenty]]). Čtyři stavy spojení jsou všechny stavy jádra: `failed` jádra, který serverová cesta nenastavovala, M48 zrušil ([[Rozhodnutí nativního jádra|N153]]). Ztrátu transakce, odmítnutou změnu a výpadek ukazují **hlášení** (následující pravidlo).
- **Hlášení** ([[M48-hlaseni-v-ui|M48]], [[Rozhodnutí nativního jádra|N151]], N153; `notices.ts`, `notice-sources.ts`): dočasné hlášení je událost, která za chvíli zmizí, ne trvalý stav jako titulek. `AppSession.notices` je seznam `AppNotice { id, kind: 'info' | 'warning' | 'error', key, params, sticky }` (nejstarší první, zmrazené pole, každá změna nové pole); text dělá `ui` z klíče překladu (ADR 0014). Jméno `notices`/`AppNotice`, protože `TitleBarNotice` v `ui` už slovo používá pro trvalé stavy titulku.
  - **Centrum** (`createNoticeCenter()`): `show({ kind, key, params? })`, `dismiss(id)` (neznámé id nic), `dismissKey(key)` (odvolá všechna hlášení s klíčem), `dispose`. Trvání podle druhu `NOTICE_DURATION_MS`: `info` 4 s, `warning` 8 s, `error` zůstane (`sticky`), dokud ho uživatel nezavře nebo zdroj neodvolá. Stejný `key` a stejné `params` (porovnání JSON) jako viditelné hlášení ho nahradí novým `id` na konci a časovač začne znovu. Nejvýš `MAX_NOTICES` = 3, nejstarší vypadne (i sticky). Časovače jsou `setTimeout`/`clearTimeout` z `globalThis`; `dismiss`, `dismissKey`, nahrazení, vypadnutí a `dispose` svůj časovač zruší, po `dispose` je `show` no-op a seznam prázdný.
  - **Zdroje** čtou jen `RemoteSession` a odmítnutí serveru, nic ze zrcadla (příprava na [[M52-tenky-klient|M52]]): událost `lost` → `warning` `notice.transactionLost` (dispečer v `onLost` dál jen zavře dialog); přechod `connection` do `offline` → sticky `error` `notice.serverUnavailable`; z `offline` (případně přes `connecting`) do `online` → `dismissKey('notice.serverUnavailable')` a `info` `notice.connectionRestored`. `retrying`, `connecting` a první `connecting` → `online` hlášení nedělají (krátký výpadek ukazuje jen titulek). `onError` dispečeru dál volá `connection.changeDropped(error)` a místo konzole `noticeOfRefusal(error)` → `show`, když není `null`.
  - **`noticeOfRefusal(error)`** – jediné místo, které z chyby dělá hlášení (M52 ho volá ze svého dispečeru beze změny): `RemoteError` `SKETCH_NOT_SOLVED` → `warning` `sketch.notSolved`; `READ_ONLY` → `error` `notice.readOnly`; opakovatelná chyba (`isRetryable`) → `null` (výpadek ukazuje titulek a hlášení o spojení, N92); jiný `RemoteError` → `error` `notice.changeRejected` s `{ reason }` (`reason`, u `UNSPECIFIED` kód gRPC); cokoli jiného (nepotvrzená změna už nejde použít) → `warning` `notice.changeDropped`.
  - **`reportError`** (`console.error`) zůstal jen pro neočekávané chyby: `close()`, nové čtení po otevření a zavření dialogu, chyby odběratelů v `read-model-view`, `retryKernel`. Z výčtu zdrojů nejde do konzole nic, takže e2e fixture hlídající konzoli nic nevypíná.
  - **Karta bez zámku** ([[Rozhodnutí nativního jádra|N146]] zůstává): `readOnly` je dál hodnota a `createEditLock` beze změny; karta, která po novém sezení přišla o zámek, úpravy dál povoluje, ale odmítnutí `READ_ONLY` teď ukáže `notice.readOnly`, takže aspoň řekne proč.
- **První pohled** (M19.2 D7): rozhoduje **první zveřejněný read model** po otevření session. Má-li tělesa, `app` zavolá `camera.fitAll()`, jinak nic. V obou případech je rozhodnuto a další read modely kameru nechají, jak ji uživatel nastavil.
- **Potvrzení** (M11): `OpenAppSessionOptions.confirm` předá `app` do `createBuiltInActions` ([[10-interakce#Vestavěné akce]]). `ui` (`App.vue`) dodá `({ key, params }) => globalThis.confirm(i18n.global.t(key, params))` – stejný nativní dialog jako mazání dokumentu v `DocumentList` ([[Rozhodnutí noční rychloakce#M11 – Další entity|R16]]).

## Vue vrstva (ui)

### Pravidla

1. UI čte stav **jen** přes `AppSession` a mění ho **jen** přes jeho API (`features.create`, `actions.run`, `editSession.setParam`…).
2. Doménové objekty, `AppSession` ani objekty Three.js **nikdy** nevkládat do `reactive()`/`ref()` (Vue by je obalilo proxy – rozbije identitu objektů, na které stojí cache regenerace, a zpomalí Three.js). Pokud je nutné je držet v komponentě: `markRaw` nebo `shallowRef`.
3. Reaktivitu zajišťuje jediný composable `useObservable`, který z `Observable<T>` [[Prezentační model|prezentačního modelu]] udělá `shallowRef` ([[0010-prezentacni-model|ADR 0010]]):

```ts
export function useObservable<T>(o: Observable<T>): Readonly<ShallowRef<T>> {
  const value = shallowRef(o.get());
  const off = o.subscribe(() => { value.value = o.get(); });
  onScopeDispose(off);
  return value;
}

// použití
const rows = useObservable(session.featureTree.rows);
```

4. **Komponenta obsahuje jen vazby a rozvržení.** Logika (co se stane po kliknutí, kdy je tlačítko aktivní, jak se řádek stromu zobrazí) patří do prezentačního modelu v `interaction`, kde se testuje bez DOM. Komponenta jen volá příkazy.
5. `AppSession` se do komponent dostane přes `provide/inject` (`useSession()`), ne přes globální proměnnou.
6. Žádný Pinia, dokud není potřeba čistě UI stav sdílený mezi vzdálenými komponentami.
7. **Štítek manipulátoru** (M18): `ui` dodá `formatValue` z `field-values.ts`: `length` → `formatNumber(round2(v)) + ' mm'`, `angle` → `formatNumber(round2(radToDeg(v))) + '°'` (`round2` = zaokrouhlení na 2 desetinná místa). Formát je stejný jako v polích dialogu a nezávisí na jazyce. Od M19 `formatValue` ani `formatHandleValue` nejsou: pole HUD ukazuje číslo z `handleValueNumber` a jednotku vedle vstupu (pravidlo 8).
8a. **HUD nápověda nástroje** (M37, [[10-interakce#Nástroje]]): komponenta `ToolHintHud.vue` v `ViewportHost` jako sourozenec elementu viewportu, nahoře uprostřed plochy (absolutní poloha, `pointer-events: none`), jeden řádek, tlumené pozadí jako HUD manipulátoru, text `t(hint.key, hint.params)`. Čte `session.tools.hint` přes `useObservable`; `null` = nic se nekreslí. Nepřekrývá HUD manipulátoru (ten je u kotvy, nápověda u horního okraje). Nápovědu mají všechny nástroje skicáře (klíče a texty v [[12-skicar#HUD nápověda kreslicích nástrojů]], [[12-skicar#Zrcadlení a pole (M36)]] a u nástrojů úprav).
8. **HUD manipulátoru** (M19, [[HUD manipulátoru]]): komponenta `ManipulatorHud.vue` v `ViewportHost` jako sourozenec elementu viewportu (do DOM viewportu se nic nevkládá) (absolutní poloha, `pointer-events` jen na samotných prvcích). Čte `session.manipulator.hud` přes `useObservable` a polohy přepočítá při změně `hud` a při `onViewChanged`. Rozvržení i zápis jsou čisté funkce v `manipulator-hud.ts` (revize M19, ADR 0010): `hudLayout(hud | null, project, area, barSize | null) → { barAt, fieldAt }` (včetně skrytí mimo plochu, `null` = skrýt; `barSize` `null` = lišta není v DOM) a `fieldCommit(text, field) → number | null` (nezměněný nebo neplatný text nebo `dragging` → `null`, jinak hodnota pro `setValue` v jednotkách dokumentu). Komponenta jen volá a přiřazuje.
   - **Lišta** (jen když `modes` není prázdné): ikony (`ti-<icon>`) s tooltipem `t(label)`, aktivní zvýrazněná, klik → `setMode(id)`. Její levý dolní roh stojí 110 px vpravo a 110 px nad průmětem `center` (za glyfy: špička šipky 98 px, oblouky 72 px; 24 px z návrhu lištu kladlo přes úchyty) (`toolbarPosition`), ořízne se dovnitř plochy pohledu. Skryje se, když průmět `center` leží mimo plochu.
   - **Pole:** `[X|Y|Z] [vstup] [mm|°]` (písmeno jen pro tint x/y/z), vystředěné na bodu z čisté funkce `fieldPosition(project(at), project(at + direction), offsetPx)` (`offsetPx` podle `HudField.kind`: `linear` 96, `angular` 88; když průměty splývají nebo `project(at + direction)` je `null`, pole jde `offsetPx` vpravo). Vstup ukazuje jen číslo (`handleValueNumber`: 2 desetinná místa, stupně u úhlu), jednotka stojí vedle. Během tahu (`dragging`) je jen pro čtení. Enter a blur zapíšou jen změněný text. Jinak editovatelný: Enter nebo blur → `parseNumber` (stupně → radiány u úhlu) → `setValue`; neplatný text → vrátí poslední hodnotu; Esc vrátí hodnotu a pustí fokus.
   - Texty: klíče režimů jsou z pluginu (`transform.mode.*`), `ui` přidává jen `manipulator.field.label` pro `aria-label` pole.
   - Mimo plochu pohledu (`project` → `null` nebo mimo) se prvek skryje.

### Vlastní dialog featury (úniková cesta)

Generovaný formulář stačí všem featurám do M15. Kdyby ho některá přerostla (náhled s vlastním ovládáním, víc kroků), dostane vlastní komponentu – v `ui`, ne v pluginu, protože plugin je prstenec 1 a Vue nezná ([[Rozhodnutí noční rychloakce#M13 – Extrude a Revolve|R80]]):

```ts
// ui/components/feature-dialogs.ts
export const FEATURE_DIALOGS: Readonly<Record<string, Component>>;   // featureType → komponenta; v M13 prázdné
export function dialogFor(featureType: string): Component;           // FEATURE_DIALOGS[type] ?? FeatureDialog
```

- `dialogFor(featureType, dialogs = FEATURE_DIALOGS)`: druhý parametr je jen pro test (registr je v M13 prázdný); bere jen vlastní klíče registru (`Object.hasOwn`, `'constructor'` není typ featury). `FEATURE_DIALOGS` je zmrazené.
- `AppShell` vykreslí `dialogFor(edit.schema.type)` s propem `edit: FeatureEditSession`; vlastní komponenta má **stejné rozhraní** jako `FeatureDialog` a stejná pravidla (stav jen přes `useObservable`, změny jen přes příkazy session, logika v prezentačním modelu v `interaction`).
- Kdy ji použít: jen když potřebné chování nejde vyjádřit schématem (`ParamSpec`, `visibleWhen`, `group`) ani novým druhem pole v registru `ParamField`. Nový druh pole je skoro vždy lepší: platí pro všechny featury a test registru ho hlídá. Vlastní dialog je vázaný na jeden typ a jeho logiku je třeba testovat zvlášť.
- Skicář tuto cestu nepoužívá: má vlastní režim (`SketchPanel`), ne dialog featury ([[12-skicar#Režim skicáře (sketcher)]]).
